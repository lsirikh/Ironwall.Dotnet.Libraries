# [통지] GIS → 웹/VMS 팀 · GOP API 서버팀 — `X-Client-Id` 는 **고정값을 쓰면 안 됩니다**

- **발신**: GIS 클라(.NET / 관제 · Ironwall 통합관제) 팀
- **수신**: 웹/VMS(SSW-VMS · SSW 통합관제 · SSW 방송) 담당
- **참조**: GOPDB(API 서버) 팀 · SSO Suite 개발 세션
- **일자**: 2026-09-30
- **성격**: 사전 통지 — **지금 고장이 난 것은 아닙니다.** 넣을 때 고정값으로 넣으면 고장 납니다

---

## 0. 한 줄

**웹이 `X-Client-Id` 를 보내기 시작할 때, `ssw-vms` 같은 고정값을 쓰면 같은 계정으로 접속한 브라우저들이 서로 로그아웃시킵니다.**
`localStorage` 에 **브라우저별 랜덤 GUID 를 한 번 심어** 그 값을 보내십시오.

---

## 1. 왜 이 통지를 합니다

GOP 서버는 세션을 **`(user_id, client_id)`** 로 가릅니다. 관리자가 `session_self_replace_enabled` 를 켜면 **같은 `client_id`** 의 옛 세션을 끊습니다 — 비정상 종료로 남은 **자기 유령 세션을 회수**하는 좋은 기능입니다.

그런데 값이 **여러 접속에서 공통**이면 "자기 옛 세션" 이 아니라 **남의 현재 세션**을 끊습니다.

서버 코드가 직접 경고합니다:

```python
# api-test-server/app/routers/auth.py:613-616
# self-replace(옵트인, 기본 off): 같은 (user_id, client_id) 세션만 교체.
#   ★공유 client_id 로 self-replace 를 켜면 상호 evict — 고유 client_id 전제.
```

**GIS 가 정확히 이 함정에 빠져 있었고, 오늘 고쳤습니다.** 같은 일이 웹에서 반복되지 않도록 미리 알립니다.

---

## 2. 지금 웹의 상태 (실측)

| 확인 | 결과 |
|---|---|
| 웹 프론트 소스(`.ts`/`.tsx`/`.js`/`.jsx`/`.vue`) 전체에서 `X-Client-Id` | **0건** |
| 그래서 서버 판정 | `_client_id` 가 `None` → self-replace 분기가 **실행되지 않음** |

➡ **지금은 상호 축출이 일어나지 않습니다.** 안전합니다.

### 다만 값이 없어서 못 누리는 것 3가지

| 잃는 것 | 내용 |
|---|---|
| 세션 식별 | 서버 세션 관리 화면에서 **어느 접속인지 구분 불가** |
| 유령 세션 회수 | 브라우저를 강제 종료하면 세션이 남고, **스스로 정리할 수 없음** |
| 동시 세션 한도 | `max_concurrent_sessions` 를 이유 없이 잡아먹음 |

그래서 **넣는 것이 맞습니다.** 다만 값을 어떻게 만드느냐가 전부입니다.

---

## 3. 🔴 하지 마십시오 — 고정값

```js
// ❌ 이렇게 하면 같은 계정으로 붙은 브라우저들이 서로 로그아웃시킵니다
headers['X-Client-Id'] = 'ssw-vms';
```

관제 현장은 **공용 운용 계정**을 여러 자리에서 함께 쓰는 경우가 흔합니다. 그 상황에서 고정값 + `self_replace` = **접속할 때마다 앞사람이 튕깁니다.**

빌드 시각·버전·호스트명을 섞는 것도 **같은 문제**입니다 — 같은 배포를 보는 브라우저는 전부 같은 값이 됩니다.

---

## 4. ✅ 이렇게 하십시오 — 브라우저 프로필별 GUID

브라우저는 머신명이 없지만, **`localStorage` 는 브라우저 프로필 단위로 분리**됩니다. 여기에 한 번만 심으면 GIS 의 "설치 고유값" 과 개념이 똑같아집니다.

```js
const KEY = 'ssw.clientId';
const PREFIX = 'ssw-vms-';   // 앱마다 다르게: ssw-central- · ssw-broadcast-

function clientId() {
  let v = null;
  try { v = localStorage.getItem(KEY); } catch { /* 사생활 보호 모드 등 */ }

  if (!v || !/^[A-Za-z0-9._:-]{1,64}$/.test(v)) {
    v = PREFIX + crypto.randomUUID().replace(/-/g, '').slice(0, 12);
    try { localStorage.setItem(KEY, v); } catch { /* 저장 못 해도 이번 세션엔 쓴다 */ }
  }
  return v;
}

// 모든 GOP 요청에 일관 부착 (로그인 포함)
headers['X-Client-Id'] = clientId();
```

### 서버 제약 (꼭 맞춰야 합니다)

| 제약 | 값 |
|---|---|
| 허용 문자·길이 | **`^[A-Za-z0-9._:-]{1,64}$`** |
| 위반하면 | 422 가 아니라 **조용히 무시**됩니다 → 값이 없는 것과 같아짐 |
| 헤더 vs 본문 | 서버는 **헤더를 먼저** 보고 본문 `client_id` 는 헤더가 없을 때만 봅니다.<br>`_client_id = request.headers.get("X-Client-Id") or login_data.client_id`<br>➡ 두 곳에 실으면 **같은 값**이어야 합니다 |

### 유의점

- `localStorage` 가 막힌 환경(사생활 보호 모드 등)에서는 **매번 새 값**이 됩니다. 접속마다 세션이 하나 쌓이지만 **상호 축출은 없습니다** — 고정값보다 훨씬 안전합니다.
- 접두(`ssw-vms-` 등)를 **앱마다 다르게** 두면 세션 관리 화면에서 어느 앱인지 바로 보입니다.
- 사용자를 식별하는 값이 아닙니다. **개인정보를 넣지 마십시오** — 랜덤이면 충분합니다.

---

## 5. SSO 를 붙일 때도 같습니다

SSO Suite 가 VMS 를 웹 앱으로 등록하는 절차를 이미 제공했습니다(OIDC 인가코드 + PKCE). 그 경로로 로그인해도 **GOP 를 부를 때의 `X-Client-Id` 는 위 규칙을 그대로 따릅니다** — SSO 등록용 `client_id`(앱 종류)와 GOP 세션 축(접속 인스턴스)은 **다른 축**입니다.

| 어디 | 값 | 뜻 |
|---|---|---|
| SSO 등록·토큰 클레임 | `ssw-vms` | **앱 종류** — 고정값이 맞습니다 |
| GOP 헤더 `X-Client-Id` | `ssw-vms-<브라우저 GUID>` | **접속 인스턴스** — 고유해야 합니다 |

GIS 도 같은 구조입니다: SSO 등록은 `gis-monitoring`(고정), GOP 헤더는 설치 고유값(`gis-<GUID12>`).

---

## 6. 서버팀께

`session_self_replace_enabled` 를 켜실 계획이 있으면 **미리 알려 주십시오.**

- **GIS**: 오늘 런타임 수정을 마쳤습니다. 다만 **이미지 복제로 설치 고유값이 복제되는 구멍**이 남아 있어 설치기 수정 전에는 완전하지 않습니다(`docs/analyses/client-id-image-clone-risk-analysis.md`).
- **웹**: 현재 헤더 미전송이라 영향 없음. 넣을 때 위 규칙을 따라야 합니다.

➡ 두 조건이 닫히기 전에 켜면 **관제석·브라우저가 서로 축출**됩니다.

## 7. 회신 부탁

1. 웹/VMS 가 `X-Client-Id` 도입 계획이 있습니까? 있으면 위 방식으로 가능한지 확인해 주십시오.
2. 문의 창구가 이 문서로 닿지 않는다면 **수신자를 알려 주십시오** — GIS 세션에는 웹팀 조율 채널이 아직 없습니다.
