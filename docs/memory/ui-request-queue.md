# UI 요청 큐

> 사용자가 화면을 보며 그때그때 올리는 요청과, 조사에서 나온 결함을 **하나도 빠뜨리지 않고** 담는 곳.
> 규칙: 새 요청은 맨 위 §열린 요청에 **받은 그대로** 적는다(요약하지 않는다). 끝나면 §끝난 것으로 옮기고 커밋 해시를 단다.
> 상태: `열림` · `진행중` · `확인대기`(사용자 답변 필요) · `완료` · `보류`
>
> 마지막 갱신: 2026-09-23 저녁 — **PC 재부팅으로 중단.** 진행중 항목의 파일별 중단 지점은 `session-context.md` 재개 포인트 참조. 작업트리 미완성 편집은 커밋 안 됨.

## 이 큐를 쓰는 법

- 사용자 요청은 **U-nn**, 조사 결함은 **D-nn**.
- 요청을 받으면 **먼저 여기 적고** 작업을 시작한다. 적기 전에 손대지 않는다.
- `확인대기` 는 사용자 답을 기다리는 것이니, 답이 오기 전에 추측으로 진행하지 않는다.
- 끝낸 항목은 지우지 않고 §끝난 것으로 옮긴다 — 무엇을 했는지 다음 세션이 알아야 한다.
- **미검증은 통과로 적지 않는다.** 눈으로 못 본 것은 `미검증` 이라고 쓴다.
