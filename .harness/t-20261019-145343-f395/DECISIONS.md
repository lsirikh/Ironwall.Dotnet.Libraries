# DECISIONS — 오버레이 이미지 다각형 자르기

## 1. 「자르기 되돌리기」를 위해 원본을 어떻게 보관할까
- options: (a) Images 테이블에 원본 경로 · 자른 상자 열 추가(DB 마이그레이션) / (b) 자른 PNG 옆에 기록 파일(`{자른 그림}.png.crop.json` — 자르기 전 그림 경로 · 그 픽셀 크기 · 자른 상자)을 두고 자르기 전 그림 파일은 지우지 않기 / (c) 되돌리기 없음
- chosen: (b) 옆 기록 파일
- why: DB · 다른 프로젝트(GMaps.Db · Models)를 건드리지 않고(공개 형식 더하기만), 원본은 이미 Images/Overlays 에 복사본으로 있으므로 지우지만 않으면 된다. 기록이 없으면 "자른 그림이 아님"으로 메뉴를 숨긴다.
- effect: 처음 불러올 때 자르면 원본 복사본(`{이름}_{시각}.png`)과 자른 그림(`{이름}_crop_{시각}.png`)이 둘 다 Images/Overlays 에 남는다(디스크 사용 ↑). 이미지 삭제 시 원본 복사본 · 기록 파일은 지우지 않는다(기존 삭제 흐름은 지도에 쓰던 파일만 지움). 바꾸려면 `ImageCropStore`(Services/ImageCropStore.cs) 의 Save/Read 를 DB 열로 옮기면 된다.

## 2. 이미 자른 그림을 다시 자르면 무엇을 자르나
- options: (a) 지금 보이는(이미 자른) 그림을 또 자른다 — 되돌리기는 한 단계씩 / (b) 늘 원본을 열고 이전 다각형을 다시 편집
- chosen: (a) 지금 그림을 자르고, 「자르기 되돌리기」는 한 단계 전 그림으로
- why: 이전 다각형을 저장 · 복원하는 기능이 목표에 없고 코드가 가장 적다. 여러 번 되돌리면 결국 원본까지 간다.
- effect: 자르기를 겹치면 기록이 사슬로 이어진다. 바꾸려면 기록에 다각형을 넣고 `RecropImageAsync` 가 기록의 Source 를 열게 하면 된다.

## 3. 「다각형으로 자르기」를 어디에 둘까
- options: 오버레이 이미지 속성 판 / 우클릭 메뉴
- chosen: 우클릭 메뉴(편집 모드, 이미지 마커) — 「다각형으로 자르기…」 · (자른 그림일 때만) 「자르기 되돌리기」
- why: 속성 판(GMapPropertyImageControl)은 이벤트 기반이라 판 · VM 양쪽에 배선이 더 들고, 동시 작업(레이어 패널 다중 선택)과 겹칠 여지가 있다. 우클릭 메뉴는 기존 레이어 순서 항목 옆에 두 줄 더하면 된다.
- effect: 속성 판에는 단추가 없다. 필요하면 속성 판에 이벤트를 하나 더해 `RecropImageAsync` 를 부르면 된다.

## 4. 다시 자를 때 경계 위경도 계산 평면
- options: (a) 미터 근사(cos 위도) 평면 / (b) 메르카토르 평면(지도 화면과 같음)
- chosen: (b) 메르카토르
- why: 지도는 경계 귀퉁이를 메르카토르 화면으로 옮겨 그 사이에 그림을 늘이고 화면에서 돌린다(GMapMarkerImageControl). 같은 평면에서 계산해야 남은 부분이 정확히 제자리이고, 자르기 ↔ 되돌리기가 정확히 서로 반대가 된다((a)는 1 mm 수준 어긋남이 시험에서 드러남).
- effect: 결과 경계의 HeightLat 는 상자 비율과 정확히 비례하지 않는다(메르카토르 높이가 비례). ImageCropMath.Reframe 한 곳.

## 5. 다각형 경계선 · 바깥 표시 어휘
- options: 점선 {4,3}/{5,3} 재사용 / 새 점선 / 실선 + 바깥 어둡게
- chosen: 그리는 중(열린 선) = 점선 {5,3}(앱의 '그리는 중 미리보기' 와 같은 뜻), 닫힌 다각형 = 실선(바깥 어두운 띠 + Primary 2px) + 바깥 ScrimModalBrush. 꼭짓점 = 원(고른 점 = 채움, 끄는 점 = 두꺼운 테두리, 닫을 수 있는 첫 점 = 크게), 선분 가운데 = 작은 속 빈 네모.
- why: {4,3} 은 선택 상자 뜻이라 피하고, {5,3} 은 이미 '그리는 중' 뜻이라 같은 뜻으로만 쓴다. 상태는 색이 아니라 모양으로(drag-first 규칙).
- effect: ImageCropCanvas.OnRender 한 곳.

## 6. 판 위치 · 모달 여부
- options: 별도 창(Window) / 지도 위 오버레이 판(OverlayWindow 패턴)
- chosen: 지도 위 오버레이 판 760×600(MapView.xaml ContentPresenter, Canvas 200,60, ZIndex 127), 머리 띠 끌기
- why: 기존 판(건물 높이 · 묶음 회전)과 같은 크롬 · 토큰을 그대로 쓰라는 목표. 창 시험 금지 규칙과도 맞는다.
- effect: 판이 떠 있어도 지도는 만질 수 있다(판 안 마우스는 판이 다 받는다). 다른 판보다 위(127).
