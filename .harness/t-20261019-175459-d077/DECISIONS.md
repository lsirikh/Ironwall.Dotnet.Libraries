# DECISIONS

## 1. 17:41 회차의 막힘 주체를 증거로 확정하지 못한 상태에서 무엇을 고칠지
- options: (a) 추정 원인 하나만 고침 (b) 재현된 실제 결함(나가기 도중 예외 → 지도 입력 막힌 채)을 고치고, 나가기 경로를 순서 · 격리로 튼튼하게 + 원인 판별 진단 줄 (c) 진단 줄만
- chosen: (b)
- why: 증거(로그 · 관찰)로는 "지도까지 WPF 입력이 라우팅되지 않았다"까지만 확정되고, 창 없는 시험에선 누름 판정이 돌지 않아 덮는 층을 재현할 수 없다. 추정 수정은 금지(증거 먼저), 진단만으론 같은 증상을 낼 수 있는 실제 결함을 남긴다.
- effect: 나가기는 상태를 내린 직후 3D 접기 · 2D 입력 되살리기를 먼저 한다. 재발 시 「[Map3D] 2D 입력 상태」 줄로 주체를 확정해 추가 수정(그때 이 줄의 "가운데=" · "막는조상=" 값을 보면 된다).

## 2. 3D 를 나갈 때 지도 IsHitTestVisible 을 무엇으로 되돌릴지
- options: (a) 늘 true (b) 펼치기 직전 로컬 값(없으면 ClearValue = 기본 true), 두 번 펼쳐도 처음 값만 적음
- chosen: (b)
- why: 과제 문구 "들어갈 때 기록하고 나올 때 되돌림 — 중간에 다른 코드가 바꾼 경우까지". 제품에서 이 값을 바꾸는 곳은 3D 뿐이라 결과는 사실상 true 와 같다.
- effect: RestoreMap2DInput 한 곳. 늘 true 로 바꾸려면 그 메서드의 첫 두 줄을 `map.IsHitTestVisible = true;` 로.

## 3. 「건물 높이」 판 닫기 중 3D 로 보내기 예외를 어떻게 다룰지
- options: (a) Leave3D 에서 try/catch (b) CloseBuildingHeightPanel 안에서 보내기만 격리(판 상태는 늘 비움)
- chosen: (b)
- why: (a)는 판 상태(_bhBuilding)가 남아 2D 에 판이 떠 있게 된다. 보내기 실패는 3D 쪽 미리보기만 못 되돌릴 뿐이고 3D 는 곧 접힌다.
- effect: 실패는 Error 로그 「[Map3D] 「건물 높이」 판 닫기 — 3D 로 보내기 실패(격리)」.
